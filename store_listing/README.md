# Store listing

Тексты для Play Console → Store presence → Main store listing.

| Файл | Куда | Лимит |
|---|---|---|
| `short_description.txt` | Short description | 80 символов |
| `full_description.txt` | Full description | 4000 символов |
| `whatsnew.txt` | Release notes у релиза | 500 символов |

## Формат: пустые строки, без HTML

⚠️ **`<b>` и `<br>` в поле описания печатаются буквально** — проверено на живой консоли
(2026-09-07). Разметку здесь обещают половина руководств в интернете, но платит за неё
читатель: он видит теги в тексте. Ничего, кроме UTF-8, не используем — заголовки это
эмодзи и капс, выделение это порядок слов.

⚠️ **Структуру держит пустая строка, и только она.** Одиночный перенос Play может
выбросить, поэтому пустая строка стоит и между блоками, и **после заголовка** — иначе
заголовок склеится с первым предложением. По той же причине здесь абзацы, а не списки
маркерами: список, у которого схлопнулись переносы, читается как каша.

⚠️ **Копировать надо из файла, а не из окна браузера или чата.** Отрендеренный текст
теряет переводы строк при копировании, и в поле приезжает одна строка на 3500 символов —
именно так листинг «слипся» дважды подряд. Открыть файл в редакторе, Ctrl+A, Ctrl+C.

## Проверка перед вставкой

```bash
node -e "const s=require('fs').readFileSync('ru-RU/full_description.txt','utf8');console.log(s.length, (s.match(/</g)||[]).length)"
```

Второе число обязано быть нулём. `wc -m` здесь врёт: в локали C он считает байты, а
кириллица в UTF-8 — два байта на букву; Play считает символы.
