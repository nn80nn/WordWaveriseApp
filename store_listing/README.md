# Store listing

Тексты для Play Console → Store presence → Main store listing.

| Файл | Куда | Лимит |
|---|---|---|
| `short_description.txt` | Short description | 80 символов, только текст |
| `full_description.txt` | Full description | 4000 символов **вместе с тегами** |
| `whatsnew.txt` | Release notes у релиза | 500 символов, **без HTML** |

## Разметка полного описания

⚠️ **Одиночный перенос строки Play выбрасывает.** Абзац открывает только пустая строка,
поэтому список, у строк которого нет `<br>`, приезжает в магазин одним сплошным текстом —
именно так листинг и «слипся» первый раз. Markdown (`**жирный**`, `#`, `-`) не понимается
вообще: звёздочки печатаются как звёздочки.

Надёжно работает: `<b>`, `<i>`, `<u>`, `<br>`, HTML-мнемоники (`&rarr;`), эмодзи и любой
UTF-8. Не работает или ломает верстку: `<a href>`, `<p>`, `<ul>`/`<li>`, `<font>`, CSS,
таблицы, картинки. `<h1>`/`<h2>` рендерятся не везде — заголовки делаем эмодзи + `<b>`.

Поэтому формат такой: строки внутри блока заканчиваются `<br>`, **последняя в блоке — нет**
(иначе между секциями двойной отступ), а блоки разделены пустой строкой.

## Проверка перед вставкой

```bash
node -e "const s=require('fs').readFileSync('ru-RU/full_description.txt','utf8');console.log(s.length)"
```

`wc -m` здесь врёт: в локали C он считает байты, а кириллица в UTF-8 — два байта на букву.
Play считает символы.
